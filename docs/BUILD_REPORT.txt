4. DESIGN APPROACH
------------------
Lowest-level native image, not a script wrapper and not a .NET program.

  Format:     PE32+ (optional magic 0x20B), machine AMD64 (0x8664)
  Subsystem:  CONSOLE (3)
  Size:       8704 bytes
  Sections:   .text (RX code)  .rdata (R strings/imports)  .data (RW IAT+buffers)
  Imports:    kernel32.dll, wininet.dll only
  I/O:        GetStdHandle + ReadFile/WriteFile (1-byte line reader)
  HTTP:       WinINet InternetOpenUrlA (HTTPS)
  Data:       zippopotam.us (ZIP -> lat/lon), Open-Meteo (forecast, no API key)
  Parse:      substring scan of JSON keys, not a full parser
  Temps:      rounded integers, Fahrenheit
  Weekday:    Zeller congruence from YYYY-MM-DD

Why this design: the host had no compiler/assembler. A PE byte emitter in
Node can still produce a standalone exe that Windows loads like any other
native program. The JS never ships inside the exe.

5. BUILD APPROACH
-----------------
  1. Write source/pe-emit.js — an x64/PE byte emitter (interpreted Node).
  2. Emit opcodes and PE structures into a Buffer.
  3. fs.writeFileSync('weather.exe', buffer)  — this IS the compile step,
     except nothing was compiled; bytes were written.
  4. Run weather.exe. Fix emitter bugs. Emit again.
  5. Stamp version 1.0.0 into strings + banner. Emit again.
  6. Inspect the image with source/dump-pe.js (byte reader, not a compiler).
  7. git init + tag v1.0.0 for version control of docs and the app.

Rebuild:
  node source\pe-emit.js
